# ACE web journey parity: Oasis to NexSteps

**Initial audit:** 6 October 2026 against `oasis-portal` and NexSteps `master`
at `a7227df78a5bcc068ce2374ce88d5ba620a4b518`. C04 reflects the merged
inventory foundation at `9aa51c88c7091974017169c0ac0a08f6dce50838` and
the step 1.3b2a API changes in this branch.

This is the implementation queue for the web portion of ACE. "Implemented"
means code exists in the repository; it does not imply a production deployment.
Each journey is complete only when its staff, parent, or student outcome works
through NexSteps' organisation/site tenancy, fixed roles and access tags,
relationship checks, release policy, and the stated entitlement. Oasis paths
below are in the read-only sibling `oasis-portal` repository. The ACE access
matrix remains the permission contract; this matrix tracks end-to-end work.

| State       | Meaning                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------ |
| Implemented | A corresponding API and web journey exist, subject to the listed parity check.                   |
| Partial     | A relevant NexSteps API, data model, or web surface exists, but the Oasis outcome is incomplete. |
| Missing     | No corresponding end-to-end NexSteps web journey was found.                                      |
