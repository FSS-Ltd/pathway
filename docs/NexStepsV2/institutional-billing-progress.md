No production payment activation, provisioning or deployment is included in these merge gates. Update each row with the checked revision, check results and merge commit before beginning the next step.

Step 3 records organisation-local child identities linked to site child profiles. An admission day is counted; a leaving day is the first day excluded. Each revision stores the complete dated period history, actor and reason. Roll confirmations retain the counted identity IDs, count and revision cutoff, so later backdated corrections do not alter them. Existing child profiles remain candidates until an administrator links and admits them; a zero roll requires explicit acknowledgement. An administrator must reconcile duplicate real-world profiles under one local reference; names and birth dates are not used for automatic identity matching.

Step 5 keeps `INSTITUTIONAL_CHECKOUT_ENABLED`, `INSTITUTIONAL_PROVIDER_WRITES_ENABLED`, the independent workflow variable `INSTITUTIONAL_BILLING_WORKER_ENABLED`, and the worker CLI switch `BILLING_WORKER_ENABLED` disabled by default. The API requires an accepted, current quote and a stable organisation-scoped checkout key; the worker claims durable operations and calls the authenticated internal billing endpoint. The test-only Stripe price script provisions or validates five monthly components only when explicitly invoked with a test key. No test prices or production settings have been changed by this branch. Stripe test-account access and a complete disposable-provider lifecycle remain required before the step 5 merge gate can pass.
